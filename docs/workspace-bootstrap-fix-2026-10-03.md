# Workspace bootstrap P1 verification — 3 October 2026

The observed PostgreSQL disconnect/bootstrap defect is fixed and the deployed product path is verified. The root cause addressed here is bootstrap's unhandled terminated database connection: no checkout validation, and no safe transaction replay after a disconnect. The database's historical reason for terminating the connection remains unknown; Neon autosuspend is not established as that reason.

## Connection guidance checked

SQLAlchemy documents that pre-ping replaces dead connections at checkout, while an in-flight disconnect loses the transaction and requires replay of the whole operation. [SQLAlchemy pooling](https://docs.sqlalchemy.org/en/20/core/pooling.html), [SQLAlchemy disconnect FAQ](https://docs.sqlalchemy.org/en/20/faq/connections.html).

Psycopg documents explicit commit/rollback and the requirement to recover a failed transaction before further work. [Psycopg 3 transactions](https://www.psycopg.org/psycopg3/docs/basic/transactions.html).

Neon's official SQLAlchemy/FastAPI guidance describes pre-ping as an option for stale connections. This supports the chosen checkout check; it does not establish the cause of this historical disconnect. [Neon connection guidance](https://neon.com/blog/deploy-a-serverless-fastapi-app-with-neon-postgres-and-aws-app-runner-at-any-scale).
